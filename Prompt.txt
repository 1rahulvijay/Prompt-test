Below is a copy-paste prompt for an AI coding model to generate a polished, interactive, single-file HTML prototype.

Create a polished, interactive, enterprise-grade HTML prototype for a product called Aurora Canvas — Governed Runtime for AI-Generated Dashboards.

The prototype will be shown to business users, senior managers, data teams, AI platform teams, and governance stakeholders. It must clearly demonstrate how employees can continue creating dashboards through the company’s existing secure web-based foundational AI chatbot while Aurora Canvas converts those dashboards into governed, refreshable, traceable enterprise assets.

Core business problem

Employees currently:

1. Upload Excel or CSV files into the company-hosted AI chatbot.
2. Ask the foundational model to create an aesthetic HTML dashboard.
3. Iterate with the chatbot several times.
4. Download a large self-contained HTML file, sometimes containing 5,000–10,000 lines of HTML, CSS, JavaScript, data, charts, and business logic.
5. Share the HTML through email, Microsoft Teams, or shared drives.
6. Recreate the dashboard when the underlying data becomes stale.

This creates several problems:

* Data becomes stale.
* Dashboard files are duplicated.
* Sharing is ungoverned.
* Business logic is buried inside HTML and JavaScript.
* Data lineage is unclear.
* Users cannot easily determine which files, sheets, columns, joins, filters, or transformations produced a number.
* The same metric may be calculated differently across dashboards.
* There is no central ownership, versioning, certification, access control, or automatic refresh.
* Users must repeatedly upload new data and regenerate the whole dashboard.

Proposed solution

Aurora Canvas does not replace the company chatbot and does not primarily generate dashboards itself.

It integrates with the existing company-hosted AI chatbot.

When a user selects Governed Dashboard Mode, the chatbot dynamically injects an approved dashboard-generation skill. This skill forces the foundational model to create a compliant, single-file HTML dashboard.

The generated HTML must continue to:

* Run independently.
* Render inside the chatbot.
* Contain all CSS and JavaScript.
* Display a complete dashboard using the uploaded data.
* Preserve the user’s chosen design and interactions.

However, the HTML must also contain embedded machine-readable metadata that Aurora Canvas can extract, including:

* Dashboard manifest
* Component IDs
* Metric definitions
* Dataset definitions
* Source-file details
* Sheet names
* Source columns
* Data types
* Cleaning steps
* Transformation steps
* Joins
* Filters
* Aggregations
* Data grain
* Refresh requirements
* Current data snapshot
* Platform data bindings
* Lineage information

The user should be able to click Publish to Aurora Canvas directly from the company chatbot.

Aurora Canvas then validates, previews, governs, publishes, shares, versions, and refreshes the dashboard.

Prototype storytelling

The prototype must communicate this narrative clearly:

Before Aurora Canvas

* Employee uploads Excel to AI.
* AI creates a beautiful but static HTML dashboard.
* Employee shares the file.
* Data becomes stale.
* The dashboard must be recreated.
* There is no ownership, refresh, lineage, governance, or central catalogue.

After Aurora Canvas

* Employee continues using the same approved company chatbot.
* Governed Dashboard Mode injects a locked skill.
* The AI produces a compliant, self-contained HTML file.
* The user publishes directly to Aurora Canvas.
* Aurora Canvas validates the package.
* Data logic and lineage are extracted.
* The dashboard is connected to Excel refresh or the gold layer.
* The visual design is preserved.
* The dashboard receives a stable link.
* Access, ownership, versioning, audit, and certification are applied.
* Data refreshes without regenerating the dashboard.
* Users access the latest approved version from a central catalogue.
